# Company types and vertical packs

Every company has a **business type** (`Company.BusinessType`) and a set of **vertical packs**
(`Company.EnabledFeatures`). The type decides which packs a company uses; a pack that is off hides
its pages in the web app and its API answers **403**. Packs sit on top of the **modules**
(`Company.EnabledModules`: Sales, Purchases, Accounting, Reports, HR, Payroll, Inventory, POS), which
the platform administrator licenses per company.

Code: `Pako.Domain/Companies/BusinessType.cs` (types, packs, presets),
`Pako.Api/Authorization/RequireCompanyFeatureAttribute.cs` (the 403), migration `AddBusinessTypes`.

## Types and their packs

| Business type | Who | Packs | Modules at creation |
| --- | --- | --- | --- |
| General | Accounting clients, mixed trades, the showcase company | all | all |
| Market | Supermarket, mini-market, butcher, kiosk, shop | grocery, onlineSales | all |
| Restaurant | Restaurant, café, bar, fast food | hospitality, events | all |
| Hotel | Hotel, guest house | hotel, hospitality, events | all |
| Services | Salon, barber, clinic, gym, repair shop | services | all |
| Pharmacy | Pharmacy | pharmacy, onlineSales | all |
| FuelStation | Fuel station with its shop | forecourt, grocery | all |
| Wholesale | Wholesale and van sales | distribution | all |
| Construction | Builder | construction | all but POS |
| RealEstate | Developer, property sales and rentals | realEstate, rentals | all but POS and Inventory |
| AutoParts | Auto parts shop | autoParts, onlineSales | all |

## Packs and what they gate

| Pack | API (403 when off) | Pages |
| --- | --- | --- |
| grocery | — (till features: weighed goods, deposits, scale labels) | Grocery till profile |
| hospitality | `pos/floors`, `pos/tables`, `pos/tabs`, `pos/production-centers`, `pos/modifier-groups`, kitchen tickets | Floor plan, menu setup, kitchen screen |
| services | `pos/resources`, `pos/appointments`, packages, memberships, `pos/repairs` | Resources, appointments, memberships, repairs |
| hotel / events | `pos/room-types`, `pos/rooms`, `pos/hotel/*`, `pos/venues`, `pos/events`, `pos/ticketed-events` | Hotel chart and setup, guest register, events, tickets |
| pharmacy | `pos/pharmacy/*` | Pharmacy; prescriptions at the till |
| forecourt | `pos/forecourt/*` | Fuel station; nozzles and fleet cards at the till |
| distribution | `distribution/*` | My day, routes, visits, van load and settlement |
| onlineSales | `pos/channels`, `pos/channel-orders` | Online orders, cash on delivery |
| autoParts | `parts/*` | Parts search, references and fitment |
| construction | `construction/*` | Construction sites |
| realEstate | `real-estate/*` | Buildings, reservations, sale contracts |
| rentals | `rentals/*` | Leases, rent run |

Sales orders, invoices, bills, stock, payroll and the plain retail till are not packs: every company
with the module has them.

## Changing a company's type or packs

- **Company administrator**: Settings → company → Business type (`PUT api/companies/{id}/business-type`).
  The packs reset to the new type's; the modules stay as licensed.
- **Platform administrator**: Platform → Companies → packs (`PUT api/platform/companies/{id}/features`),
  any combination, audited.
- Companies that existed before business types are **General** with every pack on.

## Demo data

`backend/seed/pako_demo.sql.gz` holds one company per type, an accounting firm with two clients, and
users in every role. A **new** Postgres volume (`docker compose -f backend/docker-compose.yml up -d`)
loads it on first start; an existing volume keeps its data — load the demo set with
`scripts/demo/load_demo_db.sh`. Rebuild the dump with `scripts/demo/build_demo_db.sh` (fresh
container, API on :5399, `scripts/demo/build.py`). The logins, roles and permissions are listed in
`docs/DEMO_ACCOUNTS.md` (generated by the build).
